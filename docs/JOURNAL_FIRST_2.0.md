# Trader Journal 2.0 — Journal First

نسخه 2.0 عمداً تصمیم‌گیری ستاپ را از Obsidian خارج می‌کند. تحلیل و اجرای Presentation روی PDF انجام می‌شود و Obsidian فقط نقش «ژورنال حرفه‌ای، حسابداری ریسک، ثبت تصاویر، بازبینی و تحلیل عملکرد» را دارد.

## جریان روزانه

1. باز کردن ژورنال از Ribbon یا Command Palette.
2. اگر تعهد امروز ثبت نشده باشد، متن تعهد فقط یک‌بار در همان روز تایپ می‌شود.
3. داشبورد ژورنال باز می‌شود.
4. معامله زنده یا بک‌تست مستقیماً ثبت می‌شود؛ هیچ Wizard تصمیم‌گیری بین کاربر و فرم ژورنال قرار ندارد.
5. ستاپ از روی PDF انتخاب می‌شود. اگر هنوز معلوم نیست، ثبت معامله بدون ستاپ هم مجاز است و بعداً تکمیل می‌شود.
6. سه تصویر اصلی پیشنهاد می‌شود: M15/Context، M1/Entry و Exit/After.
7. پس از بسته‌شدن معامله، R، نتیجه و Review روی همان رکورد تکمیل می‌شوند.

## داشبورد

داشبورد 2.0 روی این موارد تمرکز دارد:

- چند حساب هم‌زمان: Backtest، Demo، Prop، Competition و Live.
- موجودی فعلی و PnL هر حساب.
- Win Rate، Net R، Average R، Profit Factor و Max Drawdown.
- منحنی تجمعی R و نمودار عملکرد روزانه.
- عملکرد ستاپ‌ها.
- کیفیت ژورنال: پوشش تصاویر، Review completion، تخطی مدیریت ریسک و Chase score.
- گزارش هوشمند بازه با بهترین ستاپ، بهترین/ضعیف‌ترین روز و خطای پرتکرار.
- ذخیره گزارش Markdown برای پایان هفته یا ماه در `Trading/Reports/`.

## فلسفه

- PDF = منبع تصمیم و آموزش.
- Obsidian = منبع حقیقت ژورنال و داده.
- هیچ ستاپ جدیدی توسط ژورنال اختراع نمی‌شود.
- سرعت ثبت مهم است؛ Setup می‌تواند بعداً تکمیل شود.
- تصاویر باید تصمیم را بازسازی کنند، نه فقط نتیجه را نشان دهند.
- گزارش هفتگی/ماهانه باید رفتار، ریسک و کیفیت اجرا را در کنار سود/زیان نشان دهد.
